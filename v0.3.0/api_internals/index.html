Internals

Nothing on this page is part of the public API. These are the engine's own functions: they may change behaviour, change signature or disappear in any release, including a patch release, and nothing announces it. They are documented because the engine's own invariants are worth writing down - the order in which the scheduler invalidates and publishes is the execution model - not because anything outside the package should call them.

If you find yourself needing one of these, that is worth a report: it usually means the public API is missing something.

check_connection_validity(model, c::NodeConnection)

Validate a connection before it is registered. Raises an error unless:

  • both nodes exist in the workflow;
  • both ports exist in the corresponding node specifications;
  • the target input port is free, or declared as a MultiPort;
  • the output port datatype is a subtype of the input port datatype.

A rejected connection does not consume a connection identifier.

MetidaFlows.invalidate_unpublished! — Function
invalidate_unpublished!(model::Workflow, id::Int, ready_ports::Vector{Symbol})

Clear the consumer buffers of every :normal connection leaving a port that this execution did not publish to.

Called by execute! right after push_buffer!, and it is what keeps "there is no value" distinguishable from "there is last turn's value". Without it a node that publishes a port on one turn and not on the next leaves its consumer reading the earlier value and reporting :clean - and a consumer with an optional port can never tell that the producer went silent, which is what makes conditional evaluation work at all.

:feedback connections are left alone: their buffers are the state of a loop, which is exactly what has to survive a turn. So are :error ones, which latch a diagnosis until something reads it.

See also push_buffer!, invalidate_buffer!.

source
MetidaFlows.invalidate_stale_optional! — Function
invalidate_stale_optional!(model::Workflow, id::Int)

Clear this node's buffer for every :normal connection entering an optional port whose producer is not :clean.

The producer has not published in the current turn, so whatever sits in that buffer came from an earlier one. invalidate_unpublished! covers the producer that ran and stayed silent; this covers the producer that did not run at all, whose buffer nothing else touches - mark_dirty_downstream! deliberately leaves input buffers alone, because in a cyclic workflow they are the loop state.

Called by scheduler! with release_optional = true, for the node it is about to release, and only for one: a node that is ready under the ordinary rule has every producer :clean and nothing stale to clear.

See also isready, invalidate_buffer!.

MetidaFlows.mark_dirty_downstream! — Function
mark_dirty_downstream!(model::Workflow, id::Int)

Mark the node and everything downstream of it :dirty, following :normal edges only.

Unlike invalidate_downstream! this touches nothing but the statuses: cached output data and input buffers are left in place, because a cyclic workflow carries its loop state in those buffers.

Used by scheduler! for an ABW workflow after a node has published. Marking the whole cone - and not only the direct children - is what makes a turn independent of the order in which the connections were created: isready then holds a node back until every one of its :normal ancestors has been recomputed during this turn.

A connection entering a port with kind = :feedback is not followed: a feedback edge means "next turn", so invalidation must not propagate through it.

The walk stops at nodes that are already :dirty, which bounds the total work of one turn and terminates inside a cycle. It is iterative, so graph depth cannot overflow the stack.

MetidaFlows.execution_node_validation — Function
execution_node_validation(node::AbstractDataNode, check_input_buffer::Bool = true)

Internal function. Validate node readiness before execution.

With check_input_buffer enabled, checks that:

  • every input port that is required and of kind :normal has a value in node.input_buffer,
  • validate_node succeeds.

Optional ports and ports of kind :feedback or :error may be empty: a feedback buffer is empty on the first pass of a loop by definition.

With check_input_buffer disabled only validate_node is consulted. Both schedulers enable it, so a required :normal port left without a connection makes the node :invalid_node in either engine. A port that has a connection whose producer published nothing is a different case, caught earlier by isready.

Returns

  • true if node is ready for execution.
  • false otherwise.

Scheduling

MetidaFlows.release_optional_blocked! — Function
release_optional_blocked!(model::Workflow, queue::Vector{Int},
                          queued::Set{Int}, released::Set{Int}) -> Int

Enqueue every :dirty node that isready refuses only because of an optional port, and return how many were released.

Called by scheduler! on an ABW workflow with release_optional = true, and only when the queue has run dry. That moment is the guarantee the relaxation needs: an empty queue means nothing will execute again by itself, so a producer that is not :clean now will never be, and its optional consumers can be told so instead of waiting for it forever.

An id is recorded in released, which is what tells the queue loop to serve that node under the relaxed rule once - the loop re-checks readiness when it pops a node, and the ordinary rule would refuse it again and release it again forever. Its stale optional buffers are cleared at that point, by invalidate_stale_optional!. Nodes are queued in id order, so a run does not depend on model.nodes iteration order.

A node blocked by a required port is never released: that is a missing value the node declared it cannot work without.

MetidaFlows.setsettings_unsafe! — Function
setsettings_unsafe!(node::AbstractDataNode, settings::Dict{Symbol, <: Any})

Direct mutation of node settings without invalidation. Can be re-implemented for every node type.

Default implementation copies all provided key-value pairs into node.settings, one key at a time, so a container that is a struct rather than a Dict - see AbstractNodeFields - is written through setindex! and keeps its field types. A key it refuses, because the type does not match the field or because the field does not exist, raises an error naming the node and the key.

Warning

This function does NOT invalidate cached execution results or downstream nodes.

Use setsettings! for normal workflow operation
