Execution

Executing a single node, both schedulers, and what a failure or a stop does to the rest of a run.

Exported

Available after using MetidaFlows. These are the public API in the narrow sense: the names you cannot build or run a graph without.

MetidaFlows.execute! — Function
execute!(model::Workflow, id::Int; settings::ExecuteSettings = ExecuteSettings(),
         throw_error::Bool = false)

Execute workflow node.

Main workflow execution entry point.

Execution Stages

  1. Initialize per-run execution state and logs.
  2. Optionally detect recursive cyclic execution.
  3. Skip execution for nodes already marked :clean.
  4. Mark node as :executing.
  5. Optionally execute upstream dependencies recursively.
  6. Validate node structure and execution readiness.
  7. Validate node settings.
  8. Increment exec_n and execute node implementation via execute_unsafe!.
  9. Validate execution result.
  10. Store execution state (ready_ports).
  11. Propagate outputs downstream through input buffers.
  12. Optionally invalidate downstream nodes.
  13. Mark node as :clean.

Arguments

  • settings: per-call execution flags, see ExecuteSettings.
  • throw_error: rethrow an exception raised by execute_unsafe! after the node status and the log record have been written. With the default false the error is swallowed and reported through the status and model.log.

Returns

Vector of output port labels (Vector{Symbol}) produced during execution, or an empty vector when the node was skipped, rejected by validation or failed.

The vector is not copied: for a :clean node it is the stored ready_ports state, and otherwise it is whatever execute_unsafe! returned. Treat the result as read-only.

Status after the call

:clean on success, otherwise :invalid_node, :invalid_settings, :invalid_result or :failed.

Example

execute!(w, id)                                                    # parents pulled in
execute!(w, id; settings = ExecuteSettings(; execute_upstream = false))
execute!(w, id; throw_error = true)

MetidaFlows.failed_nodes — Function
failed_nodes(model::Workflow) -> Vector{Pair{Int, Symbol}}

Nodes a run refused to execute, as id => status pairs ordered by id.

A node counts as failed when its status is :failed - its execute_unsafe! raised - or one of :invalid_node, :invalid_settings, :invalid_result, where a validation step refused it. The result is empty when every node the run attempted finished.

:dirty is not a failure. A node downstream of a failure ends the run :dirty because it was never attempted, and so does a node below a branch a gate did not take, or the body of a cyclic workflow after its last turn. Those are consequences; the cause is in this list.

See also check_failed_nodes, getstatus.

MetidaFlows.check_failed_nodes — Function
check_failed_nodes(model::Workflow; throw_error::Bool = true) -> Bool

true when failed_nodes is empty.

With throw_error - the default - a non-empty list raises instead, naming every node and its status; what each one raised is in model.log. Without it the function only reports, returning false.

This is what scheduler!(model; strict = true) calls once the traversal is over, and it works by hand after an ordinary run just as well:

scheduler!(w)            # let everything that can finish, finish
check_failed_nodes(w)    # then fail with the list

MetidaFlows.scheduler! — Function
scheduler!(model::Workflow{DAW}; reset_mode::Symbol = :full,
           throw_error::Bool = false, strict::Bool = false,
           release_optional::Bool = false)

Execute entire data analysis workflow (DAW) using topological ordering.

This scheduler is designed for deterministic acyclic data-analysis workflows.

Execution Steps

  1. Build workflow graph.
  2. Validate graph acyclicity.
  3. Generate new workflow run_id.
  4. Apply reset_mode.
  5. Execute nodes in topological order.

Arguments

  • reset_mode: :full (default) invalidates every node via reset! and drops cached output data; :soft only marks nodes :dirty and keeps the cache; :none leaves statuses untouched, so nodes that are already :clean are not recomputed. Any other value raises an error.
  • throw_error: forwarded to execute!; aborts the run on the first node that raises instead of recording the failure, which also leaves every node after it in the order unexecuted.
  • strict: once the traversal is over, raise if any node failed - see check_failed_nodes. Unlike throw_error this lets every branch that can finish, finish, and then reports every failure at once; the workflow is left in its post-run state. throw_error wins: if it raised, this check is never reached.
  • release_optional: run a node that is held back only by a required = false port, reading nothing there instead of skipping it. Off by default. In topological order a producer that is not :clean when its consumer comes up has already had its turn - it failed, or a gate above it did not take its branch - so there is nothing left to wait for, and this is what makes required = false mean on a run what it says on the port. Any earlier run's value left in that buffer is dropped first, see invalidate_stale_optional!. A required port still holds the node back. Without the flag such a consumer ends the run :dirty.

Notes

  • Nodes are executed at most once per scheduler run.
  • A node that calls request_stop! ends the traversal: everything still ahead in the order is left :dirty. A stop is not a failure, so strict does not raise on it.
  • A node is skipped when isready reports that a producer connected through a :normal port is not :clean. In an acyclic graph traversed in topological order that happens only below a node that failed, and skipping is what keeps such a node from reading an input buffer still holding a value from an earlier run - which check_input_buffer would accept. A skipped node ends the run :dirty, as it does in ABW.
  • Upstream execution and downstream invalidation are disabled because execution order is already guaranteed by topology.
  • Required input ports are enforced (check_input_buffer stays on).
  • Cyclic workflows are rejected before execution starts, including cycles closed by a :feedback port - see makegraph. In a DAW workflow the only effect of kind = :feedback is that the port is exempt from the required-buffer check; there is no delay and no second pass.

Returns

true when the traversal completed. This is not a success flag: individual nodes may still end up :failed or :invalid_*, so check getstatus when it matters.

Example

scheduler!(workflow)
result = getdata(workflow, output_id, :result)

scheduler!(model::Workflow{ABW}; reset_mode::Symbol = :full, maxiter = 1000,
           throw_error::Bool = false, throw_warn::Bool = true,
           strict::Bool = false, release_optional::Bool = false)

Execute workflow using queue-based agent/event scheduling.

Intended for dynamic, agent-based and iterative workflows. Unlike DAW, this scheduler accepts cyclic graphs, and a node may execute several times during one call.

Execution Steps

  1. Generate a new workflow run_id and apply reset_mode.
  2. Seed the queue with every node that has no input ports, in ascending id order, so a run does not depend on model.nodes iteration order.
  3. Pop a node and execute it when isready reports that every producer connected through a :normal port is :clean; otherwise drop it - a producer finishing later re-queues it. Stop serving the queue if the node called request_stop!.
  4. For every port the execution produced, mark the child and everything downstream of it :dirty - see mark_dirty_downstream! - and enqueue the child.
  5. Enqueue, without marking, the children attached to :normal connections leaving a port the execution did not produce: no value is coming for them, and a consumer whose port is optional is ready to run with nothing. Without this step such a consumer would depend on whether it happened to be dropped from the queue before its producer went silent - a node that publishes nothing enqueues nobody, so nothing would bring it back.

Required input ports are enforced, as in DAW: a node whose required :normal port has no value at all is refused with :invalid_node instead of being run on nothing. See execution_node_validation.

Arguments

  • reset_mode: :full (default) invalidates every node via reset!, drops cached output data and clears the buffers of :feedback ports, so a cyclic workflow starts a new run instead of resuming the previous one; :soft only marks nodes :dirty and keeps both the cache and the loop state, which is how state is carried between runs; :none leaves statuses untouched, so :clean nodes are not recomputed. Any other value raises an error.

    :none is not a no-op on a cyclic workflow. execute! returns the stored ready_ports of a :clean node, step 4 propagates from them, and the children recompute - on the buffers left over from the previous run. Use :soft to continue a loop and :full to start one.

  • maxiter: maximum number of scheduler iterations before aborting execution. For a cyclic workflow this is the backstop against a loop that never converges.

  • throw_error: forwarded to execute!. Aborts the run on the first node that raises, which also leaves every branch that had not run yet unexecuted.

  • strict: once the traversal is over, raise if any node failed - see check_failed_nodes. Unlike throw_error this lets everything that can finish, finish, and then reports every failure at once; the workflow is left in its post-run state, so it can be inspected after the error is caught. throw_error wins: if it raised, this check is never reached.

  • throw_warn: warn when the seed queue is empty. Nothing is executed in that case and the nodes stay :dirty, which is otherwise silent.

  • release_optional: when the queue runs dry, release the nodes that isready holds back only because of a required = false port - see release_optional_blocked! - and go on serving the queue. Off by default. The empty queue is what makes it sound: until then a producer that is not :clean may still be about to run, and reading nothing from its port would be wrong rather than conditional. This is what lets a whole branch be skipped and the result merged back afterwards: without it a consumer waits for a producer that was itself never executed, and the run stops mid-loop with no result and no error. One :info record is appended to model.log the first time a run releases anything.

Cycles

A cycle must be closed by a connection entering a port declared with kind = :feedback; see PortSpec. Two properties make the loop run:

  • isready does not wait for the producer of a feedback edge, so the cycle has a defined entry point;
  • step 4 marks children :dirty unconditionally, so a node that already ran during this call runs again instead of short-circuiting on :clean inside execute!;
  • step 4 marks the whole downstream cone, not only the direct children, so a node is held back until every one of its :normal ancestors has been recomputed during the turn. Without it the result would depend on the order in which the connections were created, because that order is the order the queue is served in.

One consequence of marking the cone: a node below a branch that was not taken during the last turn - everything after a gate that closed the loop, for instance - ends the run :dirty rather than :clean, because it genuinely was not recomputed. "Every node is :clean" is therefore not a completion signal for a cyclic workflow.

The loop ends when a node publishes nothing that has a consumer - by returning an empty vector of ready ports, or by publishing only unconnected or :terminal ports. The queue then drains.

Every cyclic workflow needs at least one node with no input ports: a :feedback port is still an input port, so a loop on its own is never seeded and never starts. See haveinputs.

Notes

  • Nodes are executed with ExecuteSettings(false), so required input ports are not enforced here, unlike the DAW path.
  • A node with input ports but without incoming connections never becomes ready and stays :dirty.

Returns

true when the queue is drained.

Example

scheduler!(w)                             # full reset, one pass or one loop
scheduler!(w; reset_mode = :soft)         # keep cached results between runs
scheduler!(w; maxiter = 10_000)           # long-running iteration
scheduler!(w; throw_warn = false)         # a deliberately unseeded graph

Public, not exported

Part of the public API, reached as MetidaFlows.name or brought in with import MetidaFlows: name. They are documented, and a breaking change to one of them moves the version exactly as a change to an exported name does. They are simply not put in your namespace, either because you add methods to them, because they are needed rarely, or because the name is too general to take over.

MetidaFlows.execute_unsafe! — Function
execute_unsafe!(node::AbstractDataNode)

Low-level node execution interface.

This function contains node-specific execution logic. The default implementation throws an error and must be specialized for every executable node type.

Read inputs with getinputdata, write results with setdata! and return the vector of output port labels that were produced. That vector is the contract with the engine: it is stored as the ready_ports state and only connections leaving these ports are refreshed by push_buffer!. Returning a subset of the output ports is allowed.

The returned labels are taken on trust

Name only what you actually wrote. A label you did not publish - or one that is not an output port at all - is not reported: the node ends :clean, and a consumer of that port silently gets nothing, because the connection was refreshed from a port that holds no new value. The symptom appears one node downstream, which is a long way from the typo.

The vector itself is checked, though: returning a bare Symbol instead of a Vector{Symbol} raises inside the engine and leaves the node :executing.

Example

struct Doubler <: AbstractNodeType end
 
function MetidaFlows.execute_unsafe!(node::DataNode{Doubler})
    x = getinputdata(node, :in)
    setdata!(node, :out, 2x)
    return [:out]
end

Notes

Errors raised here are caught by execute!, which marks the node :failed and appends an :error record to workflow.log.
