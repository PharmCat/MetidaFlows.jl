Port metadata

What a port will carry, worked out without executing anything: see the guide for the rules a node declares.

Exported

Available after using MetidaFlows. These are the public API in the narrow sense: the names you cannot build or run a graph without.

MetidaFlows.getinputmeta — Function
getinputmeta(model::Workflow, id::Int) -> Dict{Symbol, Any}

Collect descriptions of every input port of node id, asking its producers recursively.

Keys are the input port labels of node id — taken from the connections, so a producer never needs to know which port of which consumer it feeds. Every :normal input port is present in the result: an unconnected SinglePort maps to nothing, an unconnected MultiPort to an empty Vector.

A MultiPort maps to a Vector of its producers' descriptions, ordered by ascending connection id - the same order in which getinputdata returns that port's values, so a metadata rule can be written to match the node body position for position.

Ports of kind :feedback and :error are skipped: a feedback edge closes a cycle, and following it would not terminate.

done and maxdepth are threaded through to getmeta: the first keeps a common ancestor from being described twice within one call, the second bounds the depth of the walk.

Example

getinputmeta(w, mean_id)
# Dict{Symbol, Any}(:input_data => (columns = [:Subject, :Time, :Concentration],))

MetidaFlows.getmeta — Function
getmeta(model::Workflow; maxdepth::Int = 1000) -> Dict{Tuple{Int, Symbol}, Any}

Describe every output port of every node in one walk, keyed by (node id, port label).

The point is the shared memo. getmeta memoizes only within a single call, so describing a graph port by port re-walks it from the top every time: a chain of n nodes costs n walks of O(n) where one walk of O(n) would do, and a node sitting under a diamond is described once per question instead of once in total. This form asks once.

Nothing is executed, as with the single-port form. A rule that raises takes the whole call with it - see MetaRuleError - because a half-described graph is worse than a loud failure.

m = getmeta(w)
m[(csv_id, :table)]          # (columns = [:Subject, :Time, :Concentration],)
length(m)                    # one entry per output port in the graph

See also getmeta, getinputmeta.

source
getmeta(model::Workflow, id::Int, port::Symbol)

Describe what node id will produce on its output port port, without executing anything.

Walks up the graph: the node's producers are asked first, their answers are handed to getmeta_unsafe as inmeta. The walk stops at nodes without incoming connections, and at any node for which ismetasource returns true.

Returns nothing when the answer is unknown — because the node did not implement getmeta_unsafe, because a producer up the chain did not, or because the required settings are not filled in yet. Unknown is only reported as nothing if the rule checks: a rule that reads a setting which is not there raises instead, wrapped in MetaRuleError so the node and port are named. See the Consistency section of ismetasource.

Arguments

  • maxdepth: longest chain of nodes the walk may descend into before raising. Guards against a pathological graph exhausting the stack; a node declaring ismetasource ends the walk without consuming depth.

Notes

  • Within one call each (node, output port) pair is described once: a diamond does not compute its common ancestor twice. The memo lives for the duration of the call only, so nothing can go stale between calls — a file may change on disk, and the next call sees it.
  • Nothing is cached between calls. Memoize inside the node if a source is expensive to inspect. To describe many ports at once, use the whole-graph form getmeta(model) instead of calling this one in a loop: it shares a single memo, which turns O(n²) rule invocations into O(n).
  • A node declaring ismetasource cuts the walk short, so the branches above it are never visited.
  • In a graph containing a cycle built from :normal edges the answer for a node inside the cycle depends on where the walk started. Such a graph is rejected by the DAW scheduler and never produced by ABW, where cycles are closed by :feedback edges that this walk does not follow.
  • :feedback and :error edges are not followed, so cyclic ABW workflows are safe. A cycle built from :normal edges only is detected as a back edge and yields nothing for the repeated node instead of recursing forever.

Example

getmeta(w, csv_id, :table)      # (columns = [:Subject, :Formulation, :Time, :Concentration],)

Public, not exported

Part of the public API, reached as MetidaFlows.name or brought in with import MetidaFlows: name. They are documented, and a breaking change to one of them moves the version exactly as a change to an exported name does. They are simply not put in your namespace, either because you add methods to them, because they are needed rarely, or because the name is too general to take over.

MetidaFlows.getmeta_unsafe — Function
getmeta_unsafe(node::AbstractDataNode, port::Symbol, inmeta)

Describe what the node will produce on output port port, without executing it.

This is the extension point of metadata propagation, the configuration-time counterpart of execute_unsafe!. Like it, the method sees only the node: inmeta carries the descriptions of the node's own input ports, keyed by the node's own port labels, in exactly the shape getinputdata uses:

  • SinglePort: the description, or nothing when the port is unconnected or the producer does not know;
  • MultiPort: a Vector of descriptions, ordered by ascending connection id, matching getinputdata.

The default implementation returns nothing, meaning "unknown". The shape of a description is a contract between nodes sharing a port datatype, not something the engine defines.

Rules

  • Never pass a description through unchanged unless the node really preserves it. A node that renames or drops columns must describe its own result; returning the input description would propagate a lie downstream.
  • This is not validation. nothing means "cannot tell", not "misconfigured" — checking that a configured column actually exists belongs in validate_settings and in the node body.
  • Reading a little is fine, computing is not: parse a header, not a file.

Example

# a source: reads the header only
function MetidaFlows.getmeta_unsafe(node::DataNode{ReadCSV}, ::Symbol, inmeta)
    path = get(node.settings, :file, nothing)
    (path === nothing || !isfile(path)) && return nothing
    return (columns = propertynames(CSV.File(path; limit = 0)),)
end

# a transparent node: rows are filtered, the schema is preserved
MetidaFlows.getmeta_unsafe(::DataNode{FilterRows}, ::Symbol, inmeta) = inmeta[:table]

MetidaFlows.ismetasource — Function
ismetasource(node::AbstractDataNode, port::Symbol) -> Bool

Declare that the node can describe port on its own, without asking its producers. When it returns true, getmeta stops the upward walk at this node and calls getmeta_unsafe with an empty inmeta.

The default is false, so a node describes its output from its inputs unless it says otherwise.

The predicate may depend on the node state, which is the point: a node is often a source of metadata only once it has been configured.

Consistency

ismetasource and getmeta_unsafe are written together and must agree. Reaching for inmeta[:label] in a branch declared as a metadata source raises a KeyError, because the dictionary passed there is empty — the mismatch is loud on purpose, as with validate_settings and execute_unsafe!.

The mirror half is as easy to get wrong: getmeta_unsafe is called on the not a source branch too, and there the settings it would like may be missing. A node that is a source only once configured therefore needs a method that answers for both states - usually nothing for the unconfigured one:

MetidaFlows.ismetasource(n::DataNode{Range}, ::Symbol) =
    haskey(n.settings, :lo) && haskey(n.settings, :hi)

function MetidaFlows.getmeta_unsafe(n::DataNode{Range}, ::Symbol, inmeta)
    (haskey(n.settings, :lo) && haskey(n.settings, :hi)) || return nothing
    (lo = n.settings[:lo], hi = n.settings[:hi])
end

Without that guard an unconfigured node raises KeyError from inside the walk instead of reporting "unknown", and the error surfaces far from its cause. Make the method total, not merely consistent with the predicate.

Example

# the schema is known only once the file path is set
MetidaFlows.ismetasource(node::DataNode{ReadCSV}, ::Symbol) = haskey(node.settings, :file)

# a node with an optional "schema from file" input
MetidaFlows.ismetasource(node::DataNode{Import}, ::Symbol) =
    !isempty(get(node.settings, :schema_file, ""))

function MetidaFlows.getmeta_unsafe(node::DataNode{Import}, ::Symbol, inmeta)
    haskey(node.settings, :schema_file) && return read_schema(node.settings[:schema_file])
    return inmeta[:table]                  # the branch where the node is NOT a metadata source
end

MetidaFlows.MetaRuleError — Type
MetaRuleError(id, port, cause) <: Exception

Raised when getmeta_unsafe of node id fails while describing output port port. cause is the original exception, kept so the real reason is not lost; the wrapper exists because the walk is recursive, and an error from a rule otherwise surfaces with nothing to say about where it came from.

A KeyError here almost always means the rule is not total, and there are only two ways to get there: it reads a setting that is not filled in yet, or it reads inmeta[:label] in the branch where the node declared itself a metadata source, and that dictionary is empty. An unconnected input port is not one of them - getinputmeta gives every :normal port a key, nothing when nothing is attached. See the Consistency section of ismetasource.
