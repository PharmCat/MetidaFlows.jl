API reference

The reference is split by subject, and within each page by what you can rely on. Three levels, and the difference between them matters when you upgrade:

levelwhere it isthe promise
exportedusing MetidaFlows puts it in scopethe public API in the narrow sense; it will not change or vanish without a major release
public, not exportedMetidaFlows.name, or import MetidaFlows: nameequally public - documented, and no silent changes - just not put in your namespace
internalInternalsmay change or disappear in any release, patch releases included. Do not build on these

So the rule is short: if a name is on one of the subject pages below, it is public. If it is on the Internals page, it is not.

Twenty-seven names are exported. The list is deliberately small - you can build a graph, run it and read the result with those alone:

using MetidaFlows                         # ровно этого хватает на весь граф

struct Double <: AbstractNodeType end
spec() = NodeSpec("Double", [PortSpec("In", Int, :in)], [PortSpec("Out", Int, :out)])

function MetidaFlows.execute_unsafe!(n::DataNode{Double})
    setdata!(n, :out, 2 * getinputdata(n, :in))
    return [:out]
end

That example also shows the one thing worth knowing about the second level. execute_unsafe! is the most used name in the whole package - every node implementation is a method of it - and it is deliberately not exported, because you do not call it, you add a method to it. A method for another module's function has to be written as MetidaFlows.execute_unsafe! whatever the export list says; and if the name were in scope, writing function execute_unsafe!(...) would quietly define an unrelated function in your own module and the node would never run. Julia reports nothing in that case. The same goes for every other hook: validate_*, nodesettings, getmeta_unsafe, initbuffer! and the rest.
