Add node to workflow.

Assigns a new unique node identifier and registers the node in workflow storage. Identifiers come from a monotonically increasing counter and are never reused.

Notes

A node whose status is neither :idle nor :clean is reset on insertion, which clears its settings, input buffers and execution state. A freshly created node and an already computed node are inserted unchanged, so a node may be configured before or after it joins the workflow.

MetidaFlows.execution_node_validation — Function
execution_node_validation(node::AbstractDataNode, check_input_buffer::Bool = true)

Internal function. Validate node readiness before execution.

With check_input_buffer enabled, checks that:

  • every input port that is required and of kind :normal has a value in node.input_buffer,
  • validate_node succeeds.

Optional ports and ports of kind :feedback or :error may be empty: a feedback buffer is empty on the first pass of a loop by definition.

With check_input_buffer disabled only validate_node is consulted. Both schedulers enable it, so a required :normal port left without a connection makes the node :invalid_node in either engine. A port that has a connection whose producer published nothing is a different case, caught earlier by isready.

Returns

  • true if node is ready for execution.
  • false otherwise.

MetidaFlows.invalidate_stale_optional! — Method
invalidate_stale_optional!(model::Workflow, id::Int)

Clear this node's buffer for every :normal connection entering an optional port whose producer is not :clean.

The producer has not published in the current turn, so whatever sits in that buffer came from an earlier one. invalidate_unpublished! covers the producer that ran and stayed silent; this covers the producer that did not run at all, whose buffer nothing else touches - mark_dirty_downstream! deliberately leaves input buffers alone, because in a cyclic workflow they are the loop state.

Called by scheduler! with release_optional = true, for the node it is about to release, and only for one: a node that is ready under the ordinary rule has every producer :clean and nothing stale to clear.

See also isready, invalidate_buffer!.

source
MetidaFlows.invalidate_unpublished! — Method
invalidate_unpublished!(model::Workflow, id::Int, ready_ports::Vector{Symbol})

Clear the consumer buffers of every :normal connection leaving a port that this execution did not publish to.

Called by execute! right after push_buffer!, and it is what keeps "there is no value" distinguishable from "there is last turn's value". Without it a node that publishes a port on one turn and not on the next leaves its consumer reading the earlier value and reporting :clean - and a consumer with an optional port can never tell that the producer went silent, which is what makes conditional evaluation work at all.

:feedback connections are left alone: their buffers are the state of a loop, which is exactly what has to survive a turn. So are :error ones, which latch a diagnosis until something reads it.

See also push_buffer!, invalidate_buffer!.

MetidaFlows.isready — Method
isready(model::Workflow, id::Int; wait_optional::Bool = true)

Check whether a node is ready for execution.

A node is ready when, for every connection entering a :normal input port, the producer has status :clean and, if the port is required, that producer actually published to the port this connection leaves. Connections entering ports of any other kind are not waited for.

The kind asymmetry is what makes cycles possible: a :feedback edge carries the value of the previous iteration, so requiring its producer to be :clean would deadlock - the node would wait for a producer that waits for the node.

The publication condition is what makes conditional evaluation work. A node that publishes only some of its output ports - every gate in the package does this - leaves the others with no value at all, and invalidate_unpublished! clears the consumer buffers so that nothing of the previous turn is read in their place. A consumer whose port is required therefore is not ready and does not run, in either scheduler; one whose port is required = false is ready and reads nothing, which is where a condition can be acted on.

wait_optional

An optional port's producer is waited for by default, and that wait is not about the value - it is what separates "the producer published nothing" from "the producer has not run yet". Both read nothing, and only the first one is an answer.

With wait_optional = false an optional port stops contributing to readiness altogether: a producer that is not :clean is read as absent instead of being waited for. That is only sound where the producer has already had its chance to run, so this is not something to set by hand - it is what scheduler!(model; release_optional = true) uses, in the one place each scheduler can guarantee it. Required ports are unaffected.

A node released this way may still be holding an earlier turn's value in the optional port's buffer, which invalidate_stale_optional! clears.

Notes

  • Current node status itself is not checked.
  • A port with no connection at all is a different case: this function walks connections and cannot see such a port. Completeness of required buffers is validated separately by execution_node_validation, which both schedulers enable: such a port makes the node :invalid_node.
  • A node with :normal input ports but no incoming connection is ready immediately; it just never gets enqueued unless something feeds it.

MetidaFlows.makegraph — Method
makegraph(model::Workflow)

Build directed graph representation of workflow: node identifiers become vertex names and every connection becomes an edge.

Notes

All connections are included regardless of the kind of the ports they attach to. A :feedback edge is therefore an ordinary edge here, so a graph with a feedback loop is cyclic and scheduler! for a DAW workflow rejects it. That is by design: cycles are an ABW feature.

MetidaFlows.mark_dirty! — Method
mark_dirty!(node::AbstractDataNode; soft::Bool = false)

Invalidate node execution result.

Performs the following operations:

  • sets node status to :dirty,
  • clears ready_ports,
  • clears cached output data stored in node.data.

With soft = true the last two steps are skipped: the status and the counter are reset, but ready_ports and node.data are left in place. That is what reset_mode = :soft of scheduler! uses to keep results between runs.

This function intentionally does not clear:

  • node settings,
  • input buffer,
  • execution logs.
  • execution counters/state metadata.

Returns

The node.

MetidaFlows.mark_dirty_downstream! — Method
mark_dirty_downstream!(model::Workflow, id::Int)

Mark the node and everything downstream of it :dirty, following :normal edges only.

Unlike invalidate_downstream! this touches nothing but the statuses: cached output data and input buffers are left in place, because a cyclic workflow carries its loop state in those buffers.

Used by scheduler! for an ABW workflow after a node has published. Marking the whole cone - and not only the direct children - is what makes a turn independent of the order in which the connections were created: isready then holds a node back until every one of its :normal ancestors has been recomputed during this turn.

A connection entering a port with kind = :feedback is not followed: a feedback edge means "next turn", so invalidation must not propagate through it.

The walk stops at nodes that are already :dirty, which bounds the total work of one turn and terminates inside a cycle. It is iterative, so graph depth cannot overflow the stack.

MetidaFlows.nodebuffer — Method
nodesettings(::Type) -> container
nodedata(::Type)     -> container
nodestate(::Type)    -> container
nodebuffer(::Type)   -> Dict{Symbol, Dict{Int, T}}

Fresh containers for a node of the given node type. These are the defaults of the DataNode keyword constructors and what dict_to_node builds a loaded node with, so one method here types a node everywhere - by hand, in a graph, and after a round trip through a snapshot.

Default: Dict{Symbol, Any}() for settings and data, NodeState for state, Dict{Symbol, Dict{Int, Any}}() for the input buffer. Each is called once per node, and only when the corresponding keyword is not given, so a container is never built and thrown away.

mutable struct ScaleSettings <: MetidaFlows.AbstractNodeSettings
    factor::Float64
    ScaleSettings() = new(1.0)
end
mutable struct ScaleData <: MetidaFlows.AbstractNodeData
    out::Union{Float64, Nothing}
    ScaleData() = new(nothing)
end

struct Scale <: AbstractNodeType end
MetidaFlows.nodesettings(::Type{Scale}) = ScaleSettings()
MetidaFlows.nodedata(::Type{Scale})     = ScaleData()
MetidaFlows.nodebuffer(::Type{Scale})   = Dict{Symbol, Dict{Int, Float64}}()

node = DataNode(Scale, spec_scale())
# DataNode{Scale, ScaleSettings, ScaleData, NodeState, Float64}

Specialize them independently: typed settings with Dict data is a perfectly good combination.

nodebuffer chooses the buffer's value type, not its container: the input_buffer field is declared Dict{Symbol, Dict{Int, BufferT}}, so a custom container cannot be substituted - see AbstractNodeInputBuffer. A value type narrower than Any is checked on every write, which is how a port carrying the wrong type is caught early.

See AbstractNodeFields for what a container struct has to provide.

MetidaFlows.register_node! — Method
register_node!(node::DataNode; overwrite = false, skipmode = false) -> String | Nothing
register_node!(model::Workflow; skipmode = false) -> Vector{String}

Register the type and the specification of a node in NODE_REGISTER, so that a snapshot naming it can be restored. Returns the key, which is nodetypestr of the node.

Registering a different type under a key already taken raises; overwrite replaces the entry, skipmode returns nothing instead of raising.

The Workflow form registers every node type of a graph and returns the keys it added, sorted. A graph normally holds several nodes of one type, and that is not a repeated registration: each type is registered once per call, from its first node, and the remaining nodes of that type are passed over. So register_node!(w) is the ordinary call, and the flags mean for a graph exactly what they mean for a node - what to do about a key that was already taken before this call. A type whose spec has changed is the case for overwrite = true; skipmode = true keeps whatever is registered.

Register from `__init__`, not at top level

A package that registers its nodes in top-level code loses the registration: the call runs while that package is precompiled, and a mutation of another module's global state is not captured in the precompiled image. At load time top-level code no longer runs, so the register stays empty - with no error at all.

module AcmeNodes
using MetidaFlows
struct FancyFilter <: MetidaFlows.AbstractNodeType end
fancy_spec() = NodeSpec("Fancy filter", PortSpec[], PortSpec[], [:column])

function __init__()
    MetidaFlows.register_node!(DataNode(FancyFilter, fancy_spec()))
end
end

MetidaFlows.request_stop! — Method
request_stop!(node::AbstractDataNode)

Ask the scheduler to end the run as soon as this node finishes.

Called from inside execute_unsafe! by a node that knows there is nothing left worth computing - a search that found its answer, a check that failed a precondition. What the node publishes is published as usual, so a result can travel out through a :terminal port in the same execution; what changes is that nothing more is executed.

function MetidaFlows.execute_unsafe!(n::DataNode{Found})
    setdata!(n, :answer, getinputdata(n, :in))
    request_stop!(n)
    return [:answer]
end

Both schedulers honour it: ABW stops serving the queue and DAW leaves the topological traversal. Nodes that were queued or still ahead in the order are not executed and end the run :dirty, exactly as they do below a failure - a stop is not a failure, so failed_nodes stays empty and strict does not raise. The scheduler appends an :info record to model.log naming the node that stopped it.

The flag lives in the node's NodeState and is cleared by reset!, so the next run starts clean. With reset_mode = :none nothing is reset, so a stop requested by an earlier run is still there and the next one ends on that node again.

Which node stopped a run is an ordinary query afterwards:

[id for (id, n) in w.nodes if isstoprequested(n)]

See also isstoprequested.

MetidaFlows.reset! — Method
reset!(node::AbstractDataNode)

Reset node to its initial state.

Performs the following operations:

  • sets node status to :idle,
  • clears node settings,
  • clears the contents of every input buffer, keeping the port keys,
  • resets execution state (exec_n, ready_ports, execution_id, node log),
  • clears cached output data stored in node.data.

Unlike mark_dirty!, this drops the node configuration as well, so it is meant for reusing a node object rather than for invalidation.

Returns

The node.

MetidaFlows.reset! — Method
reset!(model::Workflow; soft::Bool = false)

Invalidate the whole workflow.

Zeroes the execution counter exec_n of every node, then applies mark_dirty! to each of them, forwarding soft:

  • soft = false (default): statuses become :dirty, cached output data and ready_ports are dropped, and the buffers of :feedback input ports are cleared;
  • soft = true: only statuses are reset; cached output data and the feedback buffers survive.

Clearing the feedback buffers is what makes a full reset a full reset for a cyclic workflow: those buffers hold the state of the last turn, and a loop head that still finds it there resumes the previous run instead of starting a new one. soft = true keeps them on purpose - that is how state is carried between scheduler! calls.

This is the only place where exec_n is zeroed for the whole workflow, so the counter measures work done since the last reset! rather than since the last invalidation.

Node settings, the buffers of :normal input ports and execution logs are kept in both cases - use reset!(node) for a full per-node reset.

Returns

The workflow.
